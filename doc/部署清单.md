# 云服务器部署清单

本文档覆盖：**首次部署（一次性）** 与 **日常发版 / 回滚**。

## 0. 部署形态

一台服务器 + 一个 Docker + 一套编排（`deploy/docker-compose.yml`），共 13 个容器：

| 分类 | 容器 | 对外入口 |
|---|---|---|
| 中间件 | mysql / redis / nacos | 3306 / - / 8848（Nacos 控制台） |
| 平台服务 | gateway / user-hub-service / file-service | -（仅容器网络内） |
| 平台前端 | userhub-web | http://IP:3333（用户中心） |
| AI-PPT | ai-service / ppt-service | - |
| AI-PPT 前端 | ai-ppt-web | http://IP:3336（PPT 编辑器） |
| 题库 | question-bank-service | - |
| 题库前端 | qb-web / qb-admin | http://IP:3334（学生端）/ :3335（管理端） |

访问链路：浏览器 -> 前端 nginx 容器 -> 网关容器 -> 各后端服务容器 -> 中间件。

---

## 1. 服务器准备（一次性）

- 规格建议：**4 核 8G**（6 个 Java 服务 + Nacos + MySQL，内存是瓶颈）
- 安装 Docker（含 compose 插件）：

```bash
curl -fsSL https://get.docker.com | sh
```

- 安全组 / 防火墙放行：`3333`、`3334`、`3335`、`3336`（前端）；`8848`（Nacos 控制台，仅部署期间需要，之后建议关闭外网访问）

## 2. 放置部署文件

把以下文件放到服务器，建议目录结构：

```text
/opt/exambaby/
├── deploy/
│   ├── docker-compose.yml      # 来自 cloud-platform 仓库 deploy/ 目录
│   └── .env                    # 由 .env.example 复制并填写
├── sql/                        # 各仓库 SQL/ 目录下的脚本
│   ├── user_hub.sql            # 平台
│   ├── ai_db.sql  ppt.sql      # AI-PPT
│   └── question_bank.sql       # 题库
└── naocs/                      # 各仓库 naocs/nacos-dev/ 下的配置模板
```

## 3. 配置密钥

```bash
cd /opt/exambaby/deploy
cp .env.example .env
# 编辑 .env，填入真实 MYSQL_ROOT_PASSWORD
```

## 4. 启动中间件并初始化数据库

```bash
cd /opt/exambaby/deploy
docker compose up -d mysql redis nacos
docker compose ps          # 等 mysql 状态正常（约 30 秒）
```

建库并导入（注意：SQL 是 Navicat 导出，需先建库再按库导入）：

```bash
docker exec -i mysql mysql -uroot -p"$MYSQL_ROOT_PASSWORD" -e "
CREATE DATABASE IF NOT EXISTS user_hub DEFAULT CHARACTER SET utf8mb4;
CREATE DATABASE IF NOT EXISTS ai_db DEFAULT CHARACTER SET utf8mb4;
CREATE DATABASE IF NOT EXISTS ppt_db DEFAULT CHARACTER SET utf8mb4;
CREATE DATABASE IF NOT EXISTS question_bank DEFAULT CHARACTER SET utf8mb4;"

docker exec -i mysql mysql -uroot -p"$MYSQL_ROOT_PASSWORD" -D user_hub      < ../sql/user_hub.sql
docker exec -i mysql mysql -uroot -p"$MYSQL_ROOT_PASSWORD" -D ai_db         < ../sql/ai_db.sql
docker exec -i mysql mysql -uroot -p"$MYSQL_ROOT_PASSWORD" -D ppt_db        < ../sql/ppt.sql
docker exec -i mysql mysql -uroot -p"$MYSQL_ROOT_PASSWORD" -D question_bank < ../sql/question_bank.sql
```

## 5. 导入 Nacos 配置

浏览器打开 `http://服务器IP:8848/nacos`：

1. **新建命名空间**：命名空间 ID 填 `a1e2b3c4-d5e6-7f8a-9b0c-1d2e3f4a5b6c`（各服务配置里使用的开发命名空间；如需生产专用命名空间，要同步修改各服务 `application-prod.yml` 的 `NACOS_NAMESPACE`）
2. **逐个导入配置**（配置管理 -> 新建，Data ID 填文件名，Group 选 `DEFAULT_GROUP`，内容粘贴对应 yaml）：
   - 平台：`gateway.yaml`、`user-hub-service.yaml`、`file-service.yaml`
   - AI-PPT：`ai-service.yaml`、`ppt-service.yaml`
   - 题库：`question-bank-service.yaml`
3. **替换模板占位符为真实值**：
   - `${MYSQL_PWD:}` -> 真实数据库密码（与 `.env` 中一致）
   - `${JWT_SECRET:}` -> 生成一个随机密钥（gateway 与 user-hub 必须相同）
4. **配置 AI 模型**：ai-service 的模型配置存在数据库表 `ai_db.ai_model_config` 中（provider / apiFormat / modelName / baseUrl / apiKey），在库里填好并启用

## 6. 启动全部服务

```bash
cd /opt/exambaby/deploy
docker compose up -d
docker compose ps              # 全部 Up
```

## 7. 验证

- `http://IP:3336` -> AI-PPT 界面 -> 注册/登录 -> 建项目、生成大纲冒烟
- `http://IP:3334` / `http://IP:3335` -> 题库学生端/管理端
- `http://IP:3333` -> 用户中心
- 看日志：`docker logs -f ppt-service`（容器名即服务名）

## 8. 日常发版

```text
本地改代码 -> push main
   -> GitHub Actions 自动：CI 验证 + 打镜像推 GHCR（+ 平台仓库发布制品）
   -> 服务器：docker compose pull && docker compose up -d        （约 1 分钟）
```

服务器上**不需要** git pull、不需要构建。

## 9. 回滚

1. 在 `deploy/docker-compose.yml` 找到要回滚的服务，把 `:latest` 改成要回到的 commit 号
   （commit 号可在 GitHub 的 Images 流水线运行记录里查，或 `git log`）
2. `docker compose pull <服务名> && docker compose up -d <服务名>`

## 10. 常见问题

| 现象 | 处理 |
|---|---|
| 拉镜像提示 unauthorized | 镜像包默认私有：服务器上 `docker login ghcr.io -u myismu -p <PAT>`（token 需 `read:packages` 权限）；或在 GitHub 包设置里把镜像可见性改为 public |
| 服务启动报连不上 Nacos | `docker compose logs nacos` 确认已就绪；各服务 `NACOS_ADDR` 应为 `nacos:8848` |
| 数据库连接失败 | 检查 Nacos 里各服务数据源密码与 `.env` 的 `MYSQL_ROOT_PASSWORD` 是否一致 |
| 前端页面能开但接口 502 | 网关或对应后端服务未起来：`docker compose ps` 逐个排查，`docker logs gateway` |
| 容器时区不对 | 给对应服务加环境变量 `TZ=Asia/Shanghai` |
| 磁盘占用增长 | 上传文件在 `./data/upload`、数据库在 `./data/mysql`，注意磁盘监控 |
